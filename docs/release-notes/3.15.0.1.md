# 3.15.0.1

First release on [dd-sdk-ios 3.15.0](https://github.com/DataDog/dd-sdk-ios/releases/tag/3.15.0),
built from source for Mac Catalyst. Package ids, namespaces and the version scheme are
unchanged; the fourth component is this repository's binding revision, starting again at 1 on
the new native line.

## What's new upstream

Most of 3.15.0 lands somewhere a Catalyst app can use it, but not all of it:

- **The UK1 datacenter is now reachable** — `DDSite.Uk1()`. This is the one change with a
  managed API attached; see below.
- **KSCrash is bumped to 2.5.1** inside `DatadogCrashReporting`, which is the crash reporter
  these packages actually use.
- **WebView tracing no longer drops early requests.** Upstream's `onSessionStart` now fires only
  once the sampling information WebView Tracking depends on is in place, and WebView RUM `ddtags`
  are merged by key rather than repeated. Both reach `DatadogNet.WebViewTracking.Mac` consumers.
- **Session Replay capture fidelity** — visual effects, embedded content and gradients — is the
  bulk of the release upstream and **changes nothing here**. `DatadogNet.SessionReplay.Mac` links
  and records nothing on Catalyst, as the package table in the README says; the improvement is
  real on iOS and inert on this platform.
- A Swift-6-only crash fix for `onSessionStart` is not reachable from C# at all. It ships in the
  same binaries.

Upstream's own notes are the reference:
[3.14.0…3.15.0](https://github.com/DataDog/dd-sdk-ios/compare/3.14.0...3.15.0).

## Binding changes

One member, arriving through the usual re-sync from
[DatadogNet.iOS](https://github.com/sbokatuk/DatadogNet.iOS) — the binding sources here are
verbatim copies of that repository's, and CI enforces it:

```csharp
var configuration = new DDConfiguration(clientToken: "<CLIENT_TOKEN>", env: "production")
{
    Site = DDSite.Uk1(),
};
```

`DDSite` is a class of static factory methods, so it is `DDSite.Uk1()`, not a constant. The full
set is now `Us1()`, `Us3()`, `Us5()`, `Eu1()`, `Ap1()`, `Ap2()`, `Uk1()`, `Us1_fed()`,
`Us2_fed()`. Nothing else in the managed surface moved: the header diff upstream reports one
changed framework and one added line in it.

`OpenTelemetryApi` stays on the release 3.14.0 pinned — 3.15.0's `Cartfile.resolved` names the
same one — so `DatadogNet.OpenTelemetryApi.Mac` is a rebuild rather than an upgrade.

## Upgrading from 3.14.0.x

```diff
-<PackageReference Include="DatadogNet.RUM.Mac" Version="3.14.0.4" />
+<PackageReference Include="DatadogNet.RUM.Mac" Version="3.15.0.1" />
```

Nothing else to change. No type moved, nothing was removed or renamed, and the package set is the
same; all packages move together as they depend on each other at an exact version.
